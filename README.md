##  1. Problem Statement & Pain Points

###  ปัญหาหลัก (Problem Statement)
การบริหารจัดการงานซ่อมบำรุงอาคารสถานที่และการให้บริการยืม-คืนอุปกรณ์ภายในมหาวิทยาลัยแบบเดิม มักประสบปัญหาเรื่องความล่าช้า ข้อมูลตกหล่น ไม่สามารถติดตามสถานะการดำเนินงานได้แบบ Real-time รวมถึงขาดระบบแจ้งเตือนเจ้าหน้าที่เมื่อเกิดเหตุฉุกเฉิน ทำให้ส่งผลกระทบต่อการเรียนการสอนและการจัดกิจกรรมของนิสิตและบุคลากร

###  Pain Points ที่พบในระบบเดิม
1. **สำหรับนิสิตและบุคลากร (Student/User):**
   * **ติดตามสถานะไม่ได้:** เมื่อแจ้งซ่อมหรือขอยืมอุปกรณ์ จะไม่ทราบว่าคำขออยู่ในขั้นตอนใด หรือเจ้าหน้าที่เริ่มดำเนินการแล้วหรือยัง
   * **ยื่นเรื่องยุ่งยาก:** ไม่มีช่องทางออนไลน์ที่แยกประเภทการยื่นเรื่อง (แจ้งซ่อม vs ยืมอุปกรณ์) ชัดเจน ทำให้กรอกข้อมูลผิดพลาดบ่อยครั้ง
   * **ไม่ทราบสถานะอุปกรณ์:** ไม่สามารถตรวจสอบได้ล่วงหน้าว่าอุปกรณ์ที่ต้องการยืมนั้นว่าง (Available) หรือถูกยืมไปแล้ว (Borrowed)

2. **สำหรับเจ้าหน้าที่และผู้ดูแล (Admin):**
   * **ตกหล่นคำขอฉุกเฉิน:** ไม่มีระบบแจ้งเตือนทันทีเมื่อมีคำขอใหม่ ทำให้รับรู้ปัญหาล่าช้า
   * **ตัดสต็อก/อัปเดตสถานะด้วยมือ:** ต้องคอยอัปเดตสถานะอุปกรณ์ในระบบแยกต่างหากจากการอนุมัติคำขอ ส่งผลให้เกิดความผิดพลาดของข้อมูล (Inconsistency)
   * **จัดการข้อมูลยาก:** ข้อมูลรายการซ่อมและอุปกรณ์ปะปนกัน ขาดการจัดหมวดหมู่ (Equipment vs Facility) ที่ชัดเจน

---

##  2. กลุ่มผู้ใช้งาน (Target Users)

1. **นิสิต / บุคลากร (Student / User Role):**
   * ยื่นคำขอแจ้งอุปกรณ์ชำรุด / แจ้งซ่อมแซมสถานที่
   * ยื่นคำขอยืมอุปกรณ์สำหรับกิจกรรม
   * ติดตามสถานะคำขอของตนเอง
2. **เจ้าหน้าที่ / ผู้ดูแลระบบ (Admin Role):**
   * ตรวจสอบคำขอทั้งหมดในระบบ
   * อนุมัติ (Approved) / ปรับสถานะการดำเนินการ (Completed / Pending)
   * เพิ่ม ลบ และบริหารจัดการรายการอุปกรณ์/สถานที่ในระบบ
   * รับแจ้งเตือนคำขอใหม่ผ่าน LINE Notify เพื่อเข้าดำเนินการได้ทันที

---

##  3. Main Features & Highlights

1. **Role-Based Dynamic Access Control:**
   * แยก UI/UX ระหว่าง Student และ Admin ชัดเจนในไฟล์เดียว
2. **Request System:**
   * รองรับทั้งการ **แจ้งซ่อม (Maintenance)** และ **ยืมอุปกรณ์ (Lending)** ผ่าน Dropdown แยกประเภท
3. **Inventory Status:**
   * เมื่อ Admin เปลี่ยนสถานะคำขอเป็น `Approved` -> ระบบจะปรับสถานะอุปกรณ์เป็น `Borrowed` (ยืมอยู่) ทันที
   * เมื่อเปลี่ยนเป็น `Completed` -> ระบบจะคืนสถานะอุปกรณ์เป็น `Available` (พร้อมใช้งาน) ทันที
4. **Real-time LINE Messaging API Integration:**
   * แจ้งเตือนข้อความข้ามระบบทันทีเมื่อมีคำขอใหม่ หรือเมื่อ Admin อัปเดตสถานะ
   * รองรับการทำงานผ่าน SSL/cURL compatibility บน Production Server
5. **Security:**
   * ป้องกัน CSRF Token ในทุกฟอร์ม
   * ป้องกัน SQL Injection ด้วย Prepared Statements (`bind_param`)
   * ป้องกัน XSS ทั่วทั้งระบบด้วย Helper Function `h()` (`htmlspecialchars`)
